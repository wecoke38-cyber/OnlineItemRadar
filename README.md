# 온라인판매 액션 레이더

여러 매장이 각자 접속해서, 자기 매장 데이터를 업로드하면 "지금 스마트스토어에 등록하면 좋을 상품(즉시등록)"과 "물류센터에서 당겨와야 할 상품(창고당김)"을 자동으로 골라주는 웹앱입니다.

재고이동 레이더와 달리 **데이터를 파일에 미리 구워넣지 않습니다.** 각 매장이 접속할 때마다 자기 파일 3개를 직접 업로드하고, 모든 계산은 그 사람 브라우저 안에서만 일어납니다. 파일은 서버로 전송되지 않습니다.

## 배포 방법 (GitHub Pages)

1. 이 저장소에 `index.html`과 `robots.txt`를 **저장소 루트**에 함께 올린다 (같은 위치, 하위 폴더 아님).
2. 저장소 Settings → Pages → Source에서 배포 브랜치를 지정한다.
3. `https://<계정>.github.io/<저장소>/` 로 접속되면 완료.
4. `robots.txt`가 루트에 있어야 검색엔진 노출 차단이 실제로 적용된다 — 하위 폴더에 두면 동작하지 않는다.

## 업데이트가 필요할 때

이 도구는 로직이 바뀌지 않는 한 **데이터 갱신이 필요 없습니다** — 매장이 매번 자기 파일을 업로드하는 구조라서, 재고이동 레이더처럼 "새 데이터 받아서 파일 덮어쓰기"를 할 필요가 없습니다.

아래 상황이 생기면 Claude에게 이 README와 함께 새 `index.html`을 요청하면 됩니다:

- 회사 전산(ERP) 쪽에서 엑셀 컬럼명이나 시트 제목이 바뀐 경우 (아래 "파일 인식 로직" 참고)
- 등급 체계(즉시등록/창고당김)나 판정 기준을 바꾸고 싶은 경우
- 상위 % 기본값(현재 30%)을 바꾸고 싶은 경우

## 파일 인식 로직 (기술 참고용)

업로드된 각 파일은 헤더 행의 컬럼명 + 파일 상단 메타정보 텍스트를 보고 자동으로 종류를 판정합니다 (`detectFileType` 함수, index.html 안에 포함).

| 파일 종류 | 판정 근거 컬럼/텍스트 |
|---|---|
| 온라인판매 | `실매출`, `정상판매금액`, `취소구분` 컬럼 / "판매원 실적조회" 문구 |
| 물류재고 | `창고` 컬럼 / "점/창고구분 : 창고" 문구 |
| 점재고 | `현재재고`+`점` 컬럼(창고 컬럼 없음) / "점/창고구분 : 점" 문구 |

전산 쪽 엑셀 양식이 바뀌어 자동 인식이 안 되면, 화면에서 드롭다운으로 수동 지정할 수 있지만 — 매장마다 매번 수동으로 고쳐야 하면 번거로우니 판정 로직 자체를 갱신하는 걸 추천합니다.

**주의(중요)**: 이 회사 ERP가 내보내는 엑셀은 파일 내부의 "선언된 데이터 범위"가 실제보다 작게 잘못 기록되는 경우가 있습니다 (예: 실제 12,000행짜리 데이터인데 범위는 16행으로 기록됨). `index.html`의 `fixTruncatedRange` 함수가 이를 보정합니다 — 새로 만들 때도 이 처리를 빠뜨리면 안 됩니다.

## 등급 판정 로직 요약

1. 온라인판매 파일에서 스타일별 실매출 합계 → 전사 순위 산출 (취소구분에 "취소" 포함된 행은 제외)
2. 상위 N%(기본 30%, 화면에서 5~60% 조정 가능) 안에 드는 스타일만 대상으로 함
3. 그 스타일이 **업로드한 매장의 점재고**에 재고>0으로 있으면 → 🔴 즉시등록
4. 매장엔 없지만 **물류재고**에 있으면 → 🟠 창고당김
5. 둘 다 없으면 → 화면에 표시하지 않음(보류, 액션 없음)

스타일+컬러 단위로 매칭하며, 사이즈는 점재고 파일에서만 표시용으로 보여줍니다(물류재고는 컬러 단위로만 집계되어 사이즈 정보가 없습니다).
